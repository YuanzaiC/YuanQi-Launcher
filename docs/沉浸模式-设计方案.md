## 0. 这个页面是什么

**不是启动页，是一个休眠/观赏页。**

启动器放着不管的时候，点一下右上角的按钮，整个窗口变成无边框全屏，画面只剩风景、时间、日期和当前版本。**没有任何操作**——不能启动游戏、不能切版本、没有设置。想回去就点一下屏幕，任何位置都行。

判断标准因此只有两条：

1. 看着舒服，愿意让它在那儿挂一晚上；
2. 不烧机器，不打扰人。

功能上一律做减法。所以现在这个页面里所有按钮都被删掉了，连"启动游戏"也没有——想启动游戏，先点一下退出，回到启动器再点。这不是退步：休眠页上放一个启动按钮，等于让它随时可以被误触，而且它一旦存在，"待机"就不再是待机了。

## 1. 核心思路：直接用游戏自己的全景

不做"像我的世界"的仿制背景，而是**用游戏本身的素材**：

我的世界的标题界面是一张 360° 全景（panorama），由 6 张正方形贴图组成一个立方体，相机放在立方体内部，绕 Y 轴缓慢旋转。这一套东西就在玩家自己的游戏文件里：

```
.minecraft/assets/indexes/<版本>.json        ← 资产索引
  → minecraft/textures/gui/title/background/panorama_0.png
  → panorama_1.png … panorama_5.png
.minecraft/assets/objects/<xx>/<hash>         ← 实际文件（1024×1024）
```

拿到 6 张面之后，在网页或 WPF 里搭一个**朝内的立方体**、相机置于中心、缓慢绕 Y 轴旋转，得到的就是与游戏标题界面完全一致的观感——不是"风格相似"，是同一张画面。

字体同理：`assets/minecraft/textures/font/ascii.png` 是游戏自带的 128×128 字形图集（16×16 格，每格 8×8），按 `code & 15` / `code >> 4` 取格子就是游戏的真字体。预览里的时钟、`YUANQI`、`26.3`、`ESC` 全部是这套位图字，不是某个"像素风字体"。

> ⚠️ **版权与分发**：panorama 与 ascii 字体都是 Mojang 的资产。
> 预览目录 [assets/](assets/) 里是为了让你能直接看效果而放的副本，**不要随启动器一起分发**。
> 正式实现应当在运行时从用户自己的游戏目录读取（读取位置见 §6.2），找不到再回退到自绘背景。

## 3. 视觉规范

| 元素 | 规格 |
| --- | --- |
| 全景 | 6 面 1024×1024，立方体边长 2400px，`perspective` 1700px（约 71° 水平视角） |
| 旋转 | 绕 Y 轴 360° / 190s，线性，**只转不晃**（早期叠过 26s 周期的俯仰摆动，待机时会被看成画面在起伏，已去掉） |
| 拉丁字母/数字 | 游戏位图字 `ascii.png`，字格必须取 8 的整数倍（56/72/…/152） |
| 字宽 | 用原版字符推进表，不用统一比例，见 §3.2 |
| 中文 | 正文用微软雅黑 UI（与启动器一致）；字标「缘启」另行做成像素字，见 §3.1 |
| 字标 | canvas 4× 超采样 → 下采样到 40 格 → 二值化 → 整数块填充，见 §3.1 |
| 字标颗粒 | 2 / 3 / 4px，与右侧 YUANQI 位图字的字形像素同尺寸 |
| 时钟 | 位图字，字格 56–160，按视口高度定，5×5px 硬投影 |
| 实例名 | 位图字，字格 24–48；名字超过 8 字符退回系统字体 |
| 文字投影 | 硬阴影（无模糊），模拟游戏内文字描影 |
| 压暗 | 顶部 20% 轻压、底部 40% 渐暗、四角暗角、5% 颗粒 |
| 左上 / 左下托底 | 两处径向压暗，保证字标与文字在明亮树林上也能读 |
| 指针 | 休眠态直接 `cursor: none`——观赏页上指针没有用处 |
| 尺寸基准 | 全部按**视口高度**算，不按宽度，见 §3.4 |

### 3.1 左上角字标：自己造一套中文像素字

难点：游戏位图字只有 ASCII，`缘启` 这种中文没有现成像素字可用；直接用系统字体会和整页的像素语言脱节（第一版就是这样，中文是微软雅黑、拉丁是位图字，一眼违和）。

**v1 的做法（已废弃）**：32px 粗体直接渲染 → 按 96 阈值二值化 → 2× 放大。
问题是 32px 下「缘」的笔画只有 2–3px 宽，抗锯齿把相邻笔画糊在一起，二值化后就是一团带毛刺的白块——[对比图](images/immersive-v1-vs-v2.png) 左上角那张就是。

**v2 的做法**：**4× 超采样 → 下采样到字格 → 二值化 → 整数块填充**。

1. 在 `40 × 4 = 160px` 下渲染 `缘启`，再按包围盒裁紧
2. 平滑下采样到 **40 格宽**（`imageSmoothingQuality = 'high'`）——这一步是关键：每个字格拿到的是**真实覆盖率**，而不是低分辨率下已经丢失的笔画信息
3. alpha 按 **128** 阈值二值化，丢掉所有灰边
4. 去掉孤点（4 邻域少于 2 个邻居的像素），修掉笔画末端的毛刺
5. 用 `fillRect` 按整数倍硬填充输出，1:1 显示，不靠 CSS 缩放

**颗粒尺寸跟右侧的 `YUANQI` 走**：位图字字格 16 / 24 / 32 时，每个字形像素是 2 / 3 / 4px，字标的像素块就用同样的边长。两者颗粒一致，才是同一套语言。

**字格数下限是有讲究的**：一开始用 21px 渲染再放大 3×，`缘`（12 画）会糊成一团。40 格是这一版实测能撑住笔画密度的值——如果以后换成笔画更多的字，先把 `BASE` 调大。

> 预览里的实现见 [immersive-preview.html](immersive-preview.html) 的 `buildWordmark()`。

### 3.2 位图字：字宽、字距、像素对齐

三个容易踩的点，v1 全踩了：

**一、字宽不能用统一比例。** v1 用 `--w: .78`，字格 96 时算出 `96 × .78 = 74.88px`——小数像素。字形落在半像素边界上，浏览器只能抗锯齿，像素边缘就毛了。

**二、字距要用原版的。** 原版每个字符有自己的推进宽度（单位是 8px 字格里的像素）：数字和大小写字母是 **6**，冒号句点逗号是 **2**，空格是 **4**，`~` 是 7。用统一宽度会让 `18:37` 的冒号两侧空出一大截。

**三、字格必须是 8 的整数倍。** `ascii.png` 是 16×16 个 8×8 字格；字格尺寸不是 8 的倍数时，一个字形像素会被拉伸到非整数像素上。

三条合起来：**字格取 8 的倍数 + 字宽用原版推进值 → 每个字形宽度一定是整数像素**，不需要任何抗锯齿。预览里的 `advOf()` 就是这张表。

顺带一个坑：`<kbd class="mc-text">` 上**不要**再写 `display: block`。`.mc-text` 是 `display:flex`，被覆盖后 E / S / C 三个字形会竖着堆叠成一个方块——这个 bug 在 v2 改版时真出现过。

### 3.3 为什么去掉了溅射标语

游戏的黄色斜体标语很可爱，但这版**不放**。原因是结构性的：整页背景是 360° 旋转的全景，一个 13–14px、细笔画、高饱和的黄字，在任意固定位置都会在某个旋转角度落到明亮天空或亮色树叶上，对比度直接塌掉。

试过三个位置（字标右侧、字标下方、右上角）都不成立，靠加阴影和暗角也压不住——要么读不清，要么像贴上去的补丁。

如果确实想要这个味道，可行的做法是给它一个容器：放在底部的深色工具条里做一条静态标签，或者做成一个带深色底板的小胶囊。**不要让它直接漂在全景上。**

### 3.4 多分辨率：按高度算，不按宽度算

这一版修掉的一个隐性问题是**尺寸基准**。

v1 的时钟字格按视口**宽度**算（`innerWidth × 0.062`）。在 16:9 上没问题，但 21:9 的 3440×1440 宽度多了 40%、高度没变，算出来的字格反而更小，整块 UI 缩成一小撮贴在角落。

正确做法是**按视口高度**定，再用宽度兜一个上限：

```
时钟字格   = clamp( min(q8(H × .105), q8(W × .075)), 56, 160 )
字标颗粒   = clamp( q8(H × .0178), 16, 32 ) / 8        → 2 / 3 / 4 px
实例名字格 = clamp( q8(H × .0355), 24, 48 )
提示键帽   = clamp( q8(H × .0155), 16, 22 )            → 中文提示字号 = 键帽 × .78
```

`q8()` 是取整到 8 的倍数（位图字的硬要求）。实测结果：

| 分辨率 | 时钟字格 | 字标颗粒 | 实例名字格 |
| --- | --- | --- | --- |
| 1280×720 | 72 | 2px | 24 |
| 1600×900 | 96 | 2px | 32 |
| 1920×1080 | 112 | 2px | 40 |
| 2560×1440 | 152 | 3px | 48 |
| 3440×1440 | 152 | 3px | 48 |

对应截图：[720p](images/immersive-v2-1280x720.png) · [900p](images/immersive-v2-1600x900.png) · [1080p](images/immersive-v2-1920x1080.png) · [1440p](images/immersive-v2-2560x1440.png) · [21:9](images/immersive-v2-3440x1440.png)

窗口尺寸变化时要重算并重绘（预览里做了 120ms 防抖），否则改窗口大小后字格不再对齐，像素会重新变糊。

## 4. 过场动画

预览里可以直接点着看：打开页面会先从启动器走进来，底部控制条可随时触发「进入待机 / 退出待机」。

![启动器 → 休眠页](images/immersive-v2-from-launcher.png)

预览页还带三个只用于出图的参数（正式实现里没有）：

| 参数 | 作用 |
| --- | --- |
| `?state=sleep` | 直接进入休眠态，不等 1.7s 自动进场 |
| `?state=launcher` | 停在启动器，不自动进场 |
| `?yaw=40` | 把全景冻结在指定角度，便于出可对比的截图 |
| `?hud=0` | 隐藏底部预览控制条 |

### 4.0 三条原则

1. **进出不对称**：进入要"走进去"，可以慢一点（约 1.1s）；退出要"退出来"，必须快（约 0.42s）。退出做长了会显得迟钝，这是廉价但有效的质感来源。
2. **不做硬切**：切换的一瞬间两层必须同时在动，中间不能有"空一帧"的黑或白。做法是出图层放大淡出、入图层缩小淡入，两者重叠 200ms 左右交叉。
3. **只用 `transform` + `opacity`**：这两样能走合成层，不触发布局。全屏尺寸下任何 `width/height/margin` 动画都会掉帧。

### 4.1 进入：启动器 → 休眠页（约 1.1s）

动作方向是"穿过窗口进入风景"：启动器窗口**放大并溶解**，风景从略大处**收缩到位**。

| 时间 | 层 | 动作 |
| --- | --- | --- |
| 0 | 启动器窗口 | `scale 1 → 1.07`，`opacity 1 → 0`（550ms / 380ms） |
| 0 | 桌面底 | `opacity 1 → 0`（500ms） |
| 0 | 全景层 | `scale 1.08 → 1.00`（1050ms，`cubic-bezier(.2,.8,.25,1)`） |
| 0 | 全景层 | `opacity 0 → 1`（420ms 线性，先亮起来） |
| 50ms | 字标 | 上浮 10px + 淡入（700ms） |
| 160ms | 时钟 | 同上（800ms） |
| 260ms | 日期 | 同上 |
| 320ms | 分隔线 | 同上 |
| 360ms | 版本信息 | 同上 |
| 900ms | 返回提示 | 最后淡入 |

两个层反向缩放是关键：窗口往外撑、风景往里收，观感上像镜头穿过了窗口。**注意全景的缩放要持续到 1.05s 才停**，比窗口长——这样收尾的是风景，眼睛最后停在风景上。

因为这一版没有按钮组，中间的阶梯少了一档，整体节奏比带按钮时更松弛。

### 4.2 退出：休眠页 → 启动器（约 0.42s）

| 时间 | 层 | 动作 |
| --- | --- | --- |
| 0 | 观赏层 UI | `opacity 1 → 0`（120ms，先让文字消失，避免残影） |
| 0 | 全景层 | `scale 1 → 1.06`，`opacity 1 → 0`（320ms） |
| 80ms | 启动器窗口 | `scale 0.96 → 1`，`opacity 0 → 1`（260ms） |

注意退出时全景是**放大**退出的（继续"往里走"的惯性），不是缩回去——把进入的方向反过来会让它像录像倒放。

**触发方式是"点击任意处"**，所以有一个必须处理的细节：进入后 0.5 秒内的点击要忽略，否则触发进入的那一次点击会被同一个事件顺手当成退出，页面一闪就没。ESC 作为等价入口保留，给键盘用户。

### 4.3 实现注意（WPF）

- 全部用 `RenderTransform` + `Opacity` 的 `DoubleAnimation`，`Duration` 与上表一致，`EasingFunction` 用 `CubicEase`（`EasingMode=EaseOut`）
- **不要**给 `Margin`、`Width/Height`、`Thickness` 做动画：全屏元素上这些都是布局动画，会强制每帧重新测量排列
- 圆角与边框的收放：`BorderForm.Margin` 从 8 到 0、`RectangleGeometry.RadiusX/Y` 从 8 到 0 ——这两个可以动画，但只在 8px 范围内，代价可接受；实在要极致可以把整个窗口边框在进入前一次性置零，用覆盖层盖住那一帧
- 全景立方体的缩放：给承载 `Viewport3D` 的 `Grid` 加 `ScaleTransform`，**不要**去改相机 `Position`（那会重新计算投影矩阵）
- **点击退出要覆盖整个窗口**：在沉浸覆盖层最上层放一个透明的全尺寸 `Border`/`Grid` 接 `MouseLeftButtonUp`，别指望各个子元素分别接——子元素之间总有缝，缝里点下去会没反应

## 5. 状态清单

这个页面只有两个状态，这是它作为休眠页最重要的性质。

| 状态 | 触发 | 表现 |
| --- | --- | --- |
| 观赏中 | 进入 | 全景缓慢旋转；指针隐藏；时钟每分钟跳一次 |
| 返回 | 点击任意处 / ESC | 见 §4.2，回到启动器 |

进场是一次性的（0.7–0.8s，逐块 0.1s 错开），之后画面里只有全景在动——不叠加任何循环动效，休眠页要安静。

因为没有可点的东西，也就没有 hover、没有焦点态、没有二次确认。想离开就点一下，这是唯一的交互。

`prefers-reduced-motion` 下：所有动画压到 0.01ms，全景固定在 120° 不旋转。

## 6. 落到 WPF 的实现方案

### 6.1 全景：用 WPF 3D，不要用 WebView2

这是这次方向确认后的明确结论——**不需要嵌入浏览器**：

`Viewport3D` + 一个 `MeshGeometry3D` 立方体 + 6 个 `DiffuseMaterial`（`ImageBrush` 贴面）就够。要点：

1. 立方体每个面**同时设置 `Material` 和 `BackMaterial`**，这样相机在内部也看得到面
2. `PerspectiveCamera` 放在立方体中心（`Position = 0,0,0`），`FieldOfView` 取 70 左右
3. 旋转：给 `RotateTransform3D` 的 `AxisAngleRotation3D`（轴 `0,1,0`）做 `DoubleAnimation`，`0→360`，`Duration = 190s`，`RepeatBehavior = Forever`
4. ~~俯仰摆动~~：试过再套一层 `RotateTransform3D`（轴 `1,0,0`）做 `±2°` 的慢摆，实测在待机页上会被读成「画面在起伏」，已去掉
5. 全部走 GPU（DirectX），静止时 CPU 基本为 0，GPU 也只有个位数——这正是待机页需要的

比之前的 CSS/WebView2 方案更合适：单进程、零额外依赖、不会多出 100MB 渲染进程。

⚠️ 一个坑：`DiffuseMaterial` 在内部视角下**没有光照也可见**（Diffuse 不需要光源），但如果你用 `SpecularMaterial` 或加了 `AmbientLight` 记得别把面照暗；直接 `DiffuseMaterial` + 无光源即可保持原图亮度。

### 6.2 读取全景贴图

启动器已经知道 Minecraft 目录，运行期按索引解析即可：

```
<McFolder>/assets/indexes/<AssetIndex>.json
    objects["minecraft/textures/gui/title/background/panorama_N.png"].hash
  → <McFolder>/assets/objects/<hash[0..1]>/<hash>
```

注意：**新版客户端 jar 里这 6 张是 1×1 占位图**（1.18 之后都是），真实贴图只在 `assets/objects` 里。所以不要去解 jar，要走索引。已在 1.12.2 / 1.18.2 / 1.21.4 / 26.1.2 上验证过这个差异。

取不到时（未下载资源、目录自定义）回退：
- 优先：用 6 张打包的低码率回退图（自绘，非 Mojang 资产）
- 再退：纯色渐变 + 缓慢位移，保证页面不空

缓存策略：首次解析后把 6 张解码结果留在内存（1024² × 6 ≈ 24MB 位图，可接受）；切换实例时不重新读盘。

**素材从哪来（实际实现）**：一套全景只有一个画面，所以每次进入时随机挑一套。

| 来源 | 说明 |
| --- | --- |
| **启动器自带（默认）** | `Resources\SleepPanorama\<版本>\panorama_0..5.png`，随启动器一起发布。当前打包 **7 套**：1.12 / 1.14 / 1.15 / 1.16 / 1.18 / 1.19 / 1.20。运行时**不查索引、不碰游戏目录** |
| 资源包 | 玩家自己装的，`resourcepacks/` 下含全套 `assets/minecraft/textures/gui/title/background/panorama_0..5.png` 的文件夹或 zip，有就一起参与随机 |
| 游戏目录（仅兜底） | 自带的一套都读不到时才回退：先当前实例的索引，再扫 `assets/indexes/*.json` 的其它版本（按六个哈希去重） |

- 想加/换素材：在 `Resources\SleepPanorama` 下新建一个文件夹（名字随意，日志里会显示），放 `panorama_0..5.png` 即可，不用改代码。
- 打包脚本 `pack-setup.ps1` 会把 `Resources` 整个目录带进安装包（别漏，否则装机后没图）。
- 挑过的不会连着重复；某套读不出来会换一套重试，最多三次，不会直接掉到渐变底。
- 这 7 套是从本机 `D:\YuanQiLauncher\.minecraft\assets\objects` 里按版本索引取出来的 Mojang 资产，**只作个人自用，不要外发**。

### 6.3 字体

- 拉丁/数字：把 `ascii.png` 作为 `ImageBrush` 切开，用自绘 `FrameworkElement` 按字宽逐字绘制（和预览里 `mcText()` 的逻辑一一对应，只是换成 `DrawingContext.DrawImage`）
- 中文：`Microsoft YaHei UI`，与启动器其余部分一致
- 如果不想引入位图字，退一步用启动器自带的 `Resources/#PCL English`，风格会弱一些但零成本

> **落地时发现的一个坑**：`minecraft/textures/font/ascii.png` 在现代版本里**已经不在资源索引中**
> （1.13 起字体改由 unifont 等提供方组成，实测 1.12 / 1.18 / 1.19 / 1.21 / 26.3 共 25 个索引全都没有这一项，
> 客户端 jar 里也只有 class）。所以位图字现在走三级回退：
>
> 1. 玩家游戏目录里的 `ascii.png`（老版本 / 装了带该贴图的资源包）；
> 2. **启动器内置的像素字**——按同一套图集格式（16×16 格、每格 8×8）在内存里生成，
>    字形是自己画的 5×7 像素字（数字、大写字母、常用标点，小写复用大写），推进宽度按原版规则给；
> 3. 系统字体（兜底，正常走不到）。
>
> 第 2 级是关键：没有它，绝大多数现代版本的安装上时钟会变成普通无衬线字，整页的像素语言就断了。

### 6.4 独立窗口（当前实现）

**休眠页不在启动器窗口里**，而是放在一个单独的置顶全屏窗口里。这样主窗口从头到尾尺寸一动不动，
「启动器被瞬间放大 / 缩小」这类跳变从根上就不存在了 —— 之前试过在主窗口上改尺寸再拿幻影去盖，
不管怎么调，改尺寸的那一帧总会露出旧位图（系统行为），始终差一口气。

| 项目 | 做法 |
| --- | --- |
| 窗口 | `WindowStyle=None` + `AllowsTransparency=True` + `Topmost` + `ShowInTaskbar=False` + `Owner=FormMain`，尺寸在 `Show()` 之前就定成全屏，全程不改尺寸 |
| 底 | 根节点 `Background="Transparent"`：四周一直是真实桌面，进出都不会「先黑一下」 |
| 点击 | 最上层 `BdClick` 用 `#01000000`（alpha 必须非 0，否则层叠窗口的透明像素会把点击漏给下面的窗口） |
| 焦点 | `Show()` 后 `Activate()`；`PreviewKeyDown` 收 ESC，`Closing` 里 `e.Cancel=True` 后退出休眠，别把启动器一起带走 |
| 收起 | 动画播完后 `Hide()`。启动器窗口本来就在那个位置，所以收掉这一层等于什么都没变 |

任务栏：默认取 `Screen.WorkingArea`（保留任务栏），需要真全屏时把 `SleepCoverTaskbar` 改成 True。

### 6.5 进场 / 退场的顺序（实测踩过的坑）

进出都靠一帧「启动器幻影」衔接：幻影是进入前用 `RenderTargetBitmap` 抓下的启动器画面，
按原尺寸摆回原位，进场时放大溶解、退场时浮回来。**顺序错一步就是闪一下**：

| 阶段 | 做什么 | 为什么 |
| --- | --- | --- |
| 进场·铺场 | 先抓一帧启动器画面 → `PanSleep.Prepare()`：**先**把风景层与文字层按住（`Opacity=0`）、把幻影摆上，**再**去读字体、算度量 | 读字体要一百多毫秒，这期间窗口可能已经画出去一帧；风景那时还可见的话就会闪出一整帧场景 |
| 进场·起播 | `PlayEnter()`：风景 `1.08→1` + 淡入，幻影 `1→0` | 幻影和真实启动器画面一致，交接看不出来 |
| 退场·收尾 | 幻影浮回原位（0.96→1，260ms）→ 350ms 后 `Hide()` | 这一帧屏幕上最后画的就是启动器，收掉窗口不会有任何跳变 |

- 底色必须透明：留一层深色底，淡出时就变成「先黑一下再消失」，退出和进入都是这个毛病。
- 幻影位置用 `PhantomRectOf()` 换算（屏幕坐标减休眠页窗口原点），不要直接写 `Left/Top`。
- 幻影抓的是 `PanBack`（含 8px 圆角边距），所以摆放时也要按窗口原点对齐，否则会偏 8px。

## 7. 接口契约（已落地）

```
PageLaunchLeft.xaml      BtnImmersive  →  Handles BtnImmersive.Click
PageLaunchLeft.xaml.vb   BtnImmersive_Click()  →  FrmMain.EnterImmersiveMode()
FormMain.xaml.vb         Public Sub EnterImmersiveMode(Optional Options As Object = Nothing)
```

`EnterImmersiveMode` 已补齐为真实实现，对外契约如下（调用方不用改）：

```vb
Public Sub EnterImmersiveMode(Optional Options As Object = Nothing)   ' 进入休眠页
Public Sub ExitImmersiveMode()                                        ' 退出休眠页
Public ReadOnly Property IsSleeping As Boolean                        ' 是否在休眠态（含进场动画）
Public ReadOnly Property IsImmersive As Boolean                       ' 旧命名，等价于 IsSleeping
Public Property SleepCoverTaskbar As Boolean                          ' 是否连任务栏一起盖住，默认 False
```

页面本身是 `Controls\MySleepOverlay.xaml`，由 `FormMain.EnsureSleepWindow()` 放进独立的置顶全屏窗口
（`Content = PanSleep`），主窗口的 `PanForm` 里不再有它。
配套两个自绘控件：`MyMcText`（位图字）与 `MyWordmark`（缘启字标），
素材读取集中在 `Modules\Minecraft\ModImmersiveAssets.vb`。

进入时做的事（对应 §6.4）：抓一帧启动器画面 → 休眠页窗口摆到屏幕区域并 `Show()` →
`PanSleep.Prepare()` 铺场（按住风景与文字、把幻影摆回原位、读字体算度量）→ `PlayEnter()` 起播。
启动器窗口全程不改尺寸、不隐藏标题栏、不改界面缩放。

休眠态下 `Alt+F4` 与关闭按钮先退出休眠而不是关掉启动器；`ESC` / 点击任意处返回；
进入后 0.9s 内的点击会被忽略（否则「进入的那一下」会被同一个点击顺手带走）。


> 原按钮 `BtnStatusFolder`（"打开目录"）已由 `BtnImmersive` 取代；打开目录的入口仍保留在同页次级按钮 `BtnInstanceFolder` 上，功能没丢。
